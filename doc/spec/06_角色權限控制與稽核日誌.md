# 第六章：多角色權限控制與稽核日誌模組規格

## 1. 模組目標
確保敏捷看板與工程 RFI 在多方（營造商、業主、專案經理、技術人員）協同作業下的資料安全、權責清晰與操作軌跡追溯。

## 2. 角色權限模型 (RBAC)

系統定義四種角色：

| 角色標識 | 角色名稱 | 權限範圍 |
| :--- | :--- | :--- |
| `admin` | 系統管理員 | 擁有系統全部權限：修改看板設定、編輯/刪除任何卡片與 RFI、管理使用者與權限、查看完整系統稽核日誌。 |
| `pm` | 專案經理 | 建立與編輯卡片、調整任務排程、發佈 RFI 正式回覆裁決 (`officialAnswer`)、關閉 RFI、管理成員指派。 |
| `member` | 團隊成員 | 提報卡片與 RFI、更新個人所屬任務之檢查清單與狀態、在 RFI 討論串留言提問、上傳成果附件。 |
| `client` | 業主 / 客戶 | 檢視專案看板與甘特圖時程、提報工程疑義 RFI、查閱 RFI 官方回覆進度，無法直接刪除內部卡片或修改欄位設定。 |

## 3. 稽核日誌 (Audit Trail) 規格
1. **觸發記錄時機**：
   - 建立、刪除或編輯卡片時
   - 變更卡片所屬欄位（看板拖曳移動）
   - 提報 RFI、發表留言或裁決正式回覆時
   - 狀態更動或關鍵時程調整時
2. **日誌欄位結構 (`ActivityLog`)**：
   - `id` (string): 日誌編號
   - `entityType` (enum: `'Board' | 'Card' | 'RFI'`): 影響實體
   - `entityId` (string): 實體識別碼
   - `entityTitle` (string): 實體標題（供可讀性檢索）
   - `action` (string): 操作動作名稱（如「建立新卡片」、「拖拽變更欄位」、「更新 RFI 狀態」）
   - `details` (string): 詳細說明（如前後差異、受影響人）
   - `userId` (string): 操作人 User ID
   - `timestamp` (string, ISO): 精確時間戳
3. **查詢與檢視**：
   - 提供專屬「稽核日誌 (Audit Logs)」視圖，支援依實體類型、使用者、關鍵字與時間區間進行篩選與追溯。
